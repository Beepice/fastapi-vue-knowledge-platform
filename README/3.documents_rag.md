# Documents & RAG 模块说明

> 描述文档管理和 RAG 问答的实现机制。
> 涉及路由：`/api/documents/*`（文档管理）、`/api/embeddings/*`（RAG 问答）

---

## 1. 模块职责

### 1.1 Documents 子模块

| 子功能 | 路由 | 方法 |
|--------|------|------|
| 上传 PDF 文档 | `/api/documents/upload_documents` | POST |
| 获取所有工具 | `/api/documents/tools` | GET |
| 获取工具版本列表 | `/api/documents/tools/{tool_id}/versions` | GET |
| 获取版本下所有文档 | `/api/documents/versions/{version_id}/documents` | GET |
| 获取单个文档信息 | `/api/documents/versions/{version_id}/documents/{document_id}` | GET |
| 获取文档文件（PDF） | `/api/documents/versions/{version_id}/documents/{document_id}/file` | GET |

**核心职责**：
- 管理 Tool → Version → Document 三级结构
- 文件上传后写入磁盘，路径存数据库
- 按版本组织文档，支持工具/版本维度的查询

### 1.2 RAG 子模块

| 子功能 | 路由 | 方法 |
|--------|------|------|
| 解析并向量化文档 | `/api/embeddings/versions/{version_id}/documents/{document_id}/parse` | GET |
| 检索相似片段（调试用） | `/api/embeddings/question/search_embbedding` | GET |
| RAG 问答（SSE 流式） | `/api/embeddings/question/ask` | POST |

**核心职责**：
- PDF 解析 → Chunk 切分 → Qwen embedding → pgvector 存储
- 用户提问 → 向量化 → pgvector 召回 → LLM 生成 → SSE 流式输出

## 3. 数据模型与三级结构

### 3.1 层级关系

```
Tool（工具）
  └── Version（版本）
        └── Document（文档）
```

**示例**：

| Tool | Version | Document |
|------|---------|---------|
| Tessent | 2022.4 | Tessent_Scan.pdf |
| Tessent | 2022.4 | Tessent_ATPG.pdf |
| Tessent | 2023.1 | Tessent_Scan.pdf |
| Modus | 2022.3 | Modus_Compile.pdf |

### 3.2 表结构

| 表 | 字段 | 说明 |
|---|------|------|
| `tools` | id, tool_name | 工具名 |
| `versions` | id, tool_version, tool_id | 版本号 |
| `documents` | id, title, file_type, file_path, version_id, uploaded_by | 文档元信息 |
| `document_chunks` | id, document_id, context, chunk_idx, page_start, page_end, figure_refs, embedding | 向量化的内容块 |
| `figures` | id, img_path, document_id, figure_content | 图片提取 |
| `chunks_figures` | chunks_id, figures_id | Chunk 与图片的关联 |

## 4. 文档上传流程

### 4.1 接口定义

**请求**（multipart/form-data）：

```
POST /api/documents/upload_documents
Authorization: Bearer <token>

file: <PDF文件>
title: Tessent_Scan
tool_name: Tessent
tool_version: 2022.4
tags: scan, dft
```

**响应**：
```
201 Created
{
    "id": 1,
    "title": "Tessent_Scan",
    "file_type": "pdf",
    "file_path": "storage/uploads/user_1/tessent_2022.4/Tessent_Scan.pdf",
    "version_id": 1,
    "uploaded_by": "alice",
    "created_at": "2026-08-27T10:00:00",
    "updated_at": "2026-08-27T10:00:00"
}
```

### 4.2 链路

```
客户端 POST /api/documents/upload_documents
    ↓
路由层：receive_document_pdf()
    ↓
JWT 鉴权（get_current_user_authorizer）
    ↓
save_document() 依赖注入：
├─ 自动创建 tool（如果不存在）
├─ 自动创建 version（如果不存在）
├─ 文件写入磁盘 storage/uploads/<username>/<tool_version>/
└─ 写入 documents 表
    ↓
返回 DocumentsModel
```

### 4.3 文件路径生成规则

```
storage/uploads/<username>/<tool_version>/<title>.pdf
```

- 路径按用户名 + 版本隔离，避免冲突
- 路径存数据库，文件存磁盘

### 4.4 可能的问题

| 问题 | 现象 | 原因 | 解法 |
|------|------|------|------|
| 上传后文件 404 | PDF 下载返回 404 | `file_path` 路径错误或文件未写入 | 检查 storage 目录和文件实际路径 |
| tool/version 不存在 | 上传失败 | ON CONFLICT DO NOTHING 静默跳过 | 确认 tools/versions 表是否写入成功 |
| 重复上传 | 同一文档出现两条记录 | ON CONFLICT DO NOTHING 静默跳过 | 暂不处理，后续可加幂等逻辑 |

## 5. RAG 向量化流程（parse）

### 5.1 接口定义

```
GET /api/embeddings/versions/<version_id>/documents/<document_id>/parse
Authorization: Bearer <token>
```

**无响应体**，执行完成后返回 200。

### 5.2 链路

```
触发 parse 接口
    ↓
1. 获取文件路径（从 documents 表）
    ↓
2. PDFParser 解析 PDF：
   ├─ pymupdf：提取文本块、布局、标题层级
   ├─ pdfplumber：提取表格
   └─ 过滤：chunk 文本 < 10000 字符（避免超长截断）
    ↓
3. EmbeddingService.embed_chunks()：
   ├─ 批量调用 Qwen embedding（text-embedding-v4）
   └─ 每 10 条一个批次
    ↓
4. EmbeddingRepository.upsert_document_embedding()：
   ├─ 写入 document_chunks 表（embedding 存为 pgvector）
   ├─ 写入 figures 表
   └─ 建立 chunks_figures 关联
    ↓
完成（无返回）
```

### 5.3 PDF 解析细节

**pymupdf + pdfplumber 双引擎**：

| 引擎 | 用途 |
|------|------|
| pymupdf | 主引擎，提取文本、布局、标题层级 |
| pdfplumber | 辅助，提取表格 |

**Chunk 切分策略**：
- 基于页面和内容块自然分割
- 单个 chunk 文本长度上限 10000 字符（防止超长）
- 每个 chunk 记录 `page_start` 和 `page_end`（页码范围）

### 5.4 Embedding 向量化

**配置**：

| 参数 | 值 |
|------|---|
| 模型 | text-embedding-v4（Qwen） |
| 批次大小 | 10 条/批 |
| 向量维度 | 1024（Qwen text-embedding-v4 默认） |
| 存储格式 | pgvector `vector` 类型 |

**批量处理**：每 10 条为一个 HTTP 请求批次，减少 API 调用次数。

### 5.5 向量检索（召回）

**SQL（embedding.sql）**：
```sql
SELECT ...
FROM document_chunks
WHERE embedding::vector <=> :query_embedding::vector < 0.4
LIMIT :top_k
```

**说明**：
- `<=>` 是 pgvector 的余弦距离操作符
- `< 0.4` 是距离阈值（值越小越相似）
- `LIMIT top_k` 限制返回条数

**当前参数**：

| 参数 | 值 | 说明 |
|------|---|------|
| 距离阈值 | **0.4**（当前补丁值） | 余弦距离小于此值才返回 |
| top_k | 5（默认） | 最多返回 5 个 chunk |

**说明**：当前阈值为临时补丁，待混合检索实现后可下调。加 BM25 混合检索后，可降低纯向量召回的阈值要求，提升准确率。

### 5.6 可能的问题

| 问题 | 现象 | 原因 | 解法 |
|------|------|------|------|
| 召回效果差 | 查不到相关内容 | 距离阈值 0.4 或 chunk 粒度问题 | 当前 0.4 为补丁值，待加 BM25 混合检索后可调低；优化 chunk 切分策略 |
| PDF 内存爆 | 解析大 PDF 时内存飙升 | pymupdf 缓存未释放 | 项目已用 `del _pages` 释放缓存 |
| 表格内容丢失 | 召回内容缺表格 | pdfplumber 提取失败 | 单独检查表格区域，手动补充 |
| embedding API 429 | Qwen API 限流 | 请求过快 | 降低批次大小，加重试 |

## 6. RAG 问答流程（ask）

### 6.1 接口定义

**请求**：
```
POST /api/embeddings/question/ask
Authorization: Bearer <token>
Content-Type: application/json

{
    "params": {
        "question": "什么是 ATPG？",
        "top_k": 5
    }
}
```

**响应**（SSE 流式）：
```
Content-Type: text/event-stream

data: 你
data: 好
data: ，

data: ATPG (Automatic Test Pattern Generation) 是...

[DONE]
```

### 6.2 链路

```
客户端 POST /api/embeddings/question/ask
    ↓
1. EmbeddingService.ueser_question()：
   └─ 将用户问题向量化（Qwen embedding）
    ↓
2. EmbeddingRepository.search_chunks_by_embedding()：
   └─ pgvector 召回最相似的 top_k 个 chunk
    ↓
3. build_prompt_text()：
   └─ 将召回的 chunk 填入 Prompt 模板
       格式：[1] 文档名:xxx 页码:1-3 内容:...
    ↓
4. OpenAiService.openai_api()：
   └─ 调用 Qwen3.5-Plus 生成答案（SSE 流式）
    ↓
前端逐块渲染（打字机效果）
```

### 6.3 Prompt 模板

```
你是一个专业的知识库助手。请严格基于下面的资料使用中文回答用户问题。
【回答规则】
1. 基于参考文档,使用中文回答
2. 必须给出参考文档的来源，需要文档名和页码:
3. 没找到相关资料必须指明"信息不足"
4. 简洁明了，步骤尽量清晰

【参考资料】
[1] 文档名:Tessent_ATPG 页码:5-7 内容:...
[2] 文档名:Tessent_Scan 页码:12-15 内容:...

【用户问题】
什么是 ATPG？
```

### 6.4 流式输出机制

**后端**：
- 使用 `StreamingResponse` + async generator
- LLM 逐 token 返回，后端逐 chunk yield
- 结束时发送 `[DONE]` 标记

**前端**：
- 用 `fetch` + `ReadableStream` 读取 SSE
- 按 `\n\n` 分割 data 帧
- 过滤掉 `[DONE]` 标记后追加到页面

**SSE 帧格式**：
```
data: <LLM输出的一个chunk>

[DONE]
```

### 6.5 可能的问题

| 问题 | 现象 | 原因 | 解法                                            |
|------|------|------|-----------------------------------------------|
| 召回内容不相关 | LLM 答非所问 | 距离阈值过高或 chunk 切分不好 | 调阈值 0.4，修改chunk规则                             |
| 流式中断 | 前端收到部分内容后停止 | LLM 超时或网络断 | 加超时配置，重试                                      |
| 信息不足仍回答 | LLM 瞎编 | 召回 0 条但 Prompt 规则会提示"信息不足" | 当前由 Prompt 模板约束，召回为空时仍调 LLM，由 LLM 按规则输出"信息不足" |
| 引用页码不准 | LLM 引用了错误的页码 | chunk 可能跨页，page_start/page_end 不精确 | 优化 chunk 切分逻辑，合并时记录准确页码                       |

## 7. 文档预览流程（PDF 嵌入式查看）

### 7.1 链路

```
前端 DocumentView 组件
    ↓
<iframe :src="`/api/documents/versions/${versionId}/documents/${docId}/file?token=${token}`">
    ↓
后端路由：get_document_file(version_id, document_id)
    ↓
1. 查 documents 表，获取 file_path
2. 用 FileResponse 返回 PDF 文件
    ↓
浏览器直接在 iframe 里渲染 PDF
```

### 7.2 同源访问说明

当前端通过 FastAPI 托管 Vue3（`公网IP`）访问时：
- 前端和后端同源
- iframe 请求 PDF → `公网IP:8000/api/.../file?token=xxx`
- 浏览器不带 Origin 头（iframe 请求是顶级导航或同源子资源）
- CORS 不触发 ✅

## 9. 已知限制与优化方向

| 问题 | 当前状态                  | 优化方向                                      |
|------|-----------------------|-------------------------------------------|
| 召回率不稳定 | 距离阈值 0.4，可能漏掉相关 chunk | 调阈值、增大 top_k、加 BM25 混合检索，设置ivflat probs数量 |
| chunk 粒度固定 | 按标题自然分割，内容过长或过短       | 进一步语义切分（Semantic Chunking）                |
| 无历史记录 | 每次问答独立，无上下文           | 增加对话历史表                                   |
| 无引用高亮 | 回答有引用，但前端无法高亮原文       | 返回 chunk 对应 PDF 坐标，前端高亮                   |
| 单文档召回 | 当前召回不限制 document_id   | 多文档场景需加 document_id 过滤                    |
